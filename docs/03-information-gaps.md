# Границы достоверности и вопросы для дальнейшей аналитики

## 1. Подтверждённые сведения

На основании имеющегося описания подтверждено:
- рассматривается функциональность обращений в личном кабинете лизингополучателя;
- предусмотрены четыре направления: реструктуризация, заказ справки о задолженности, страховые случаи и изменение НДС;
- тема изменения НДС возникла после повышения ставки НДС до 22%;
- у клиентов появились вопросы по графику платежей и несогласие;
- обращения по теме НДС включают как запросы на разъяснение, так и обращения с несогласием.

## 2. Неизвестные детали

В доступном описании пока отсутствуют подтверждения по следующим аспектам:

| Область | Что требуется выяснить |
|---|---|
| Пользователи и доступ | Кто может создавать обращения и какие есть ограничения |
| Точки входа | Как клиент попадает в форму обращения |
| Формы | Поля, типы данных, обязательность, значения списков |
| Валидации | Проверки и сообщения об ошибках |
| Вложения | Допустимые форматы, размеры и ограничения |
| Отправка | Условия успешной регистрации и обработка ошибок |
| Жизненный цикл | Статусы, переходы, повторная отправка или отзыв |
| Обработка | Ответственные роли и последовательность действий |
| Коммуникации | Уведомления и отображение ответа клиенту |
| Интеграции | Внешние и внутренние системы, если они участвуют |
| Нефункциональные требования | Безопасность, доступность, производительность и аудит |

## 3. Риски аналитического описания

- Нельзя превращать предположения о полях и статусах в фактические требования.
- Нельзя описывать автоматический перерасчёт или изменение графика без подтверждения.
- Нельзя заявлять о конкретных интеграциях или архитектуре без исходных данных.
- Нельзя указывать фактические сроки, SLA или показатели эффективности без источника.

## 4. План дальнейшего уточнения

1. Получить описание текущего пользовательского пути или макеты.
2. Зафиксировать поля и правила для каждого типа обращения.
3. Уточнить процесс после отправки.
4. Согласовать статусы, уведомления и отображение результата.
5. При наличии оснований описать интеграционные взаимодействия в обезличенном виде.
6. Подготовить проверяемые критерии приёмки и трассировку требований.
